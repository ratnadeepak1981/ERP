## 1. Overview

This register documents all security, permission, and architectural discrepancies identified during the comprehensive audit of ApexERP.
Findings are ranked by severity: **CRITICAL**, **HIGH**, **MEDIUM**, and **LOW**.

---

## 2. Consolidated Finding Matrix

| Finding ID | Severity | Module / Screen | Location (File & Line) | Expected Behaviour | Actual Behaviour | Risk & Impact | Recommended Minimal Correction |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **GAP-SEC-01** | **CRITICAL** | Security / User Management | `Backend/ERP/API/Features/Security/UserController.cs` | Every user mutation (`POST`, `PUT`, `DELETE`) must require `USER.CREATE`, `USER.EDIT`, `USER.DELETE`. | Controller only has `[Authorize]` at class level. Endpoints have no `[RequirePermission]` attribute. | Any authenticated tenant user (e.g. Viewer) can create, edit, or deactivate other users. | Decorate `CreateUser` with `[RequirePermission("USER.CREATE")]`, `UpdateUser` with `[RequirePermission("USER.EDIT")]`, and `DeactivateUser` with `[RequirePermission("USER.DELETE")]`. |
| **GAP-SEC-02** | **CRITICAL** | Security / Role Management | `Backend/ERP/API/Features/Security/RoleController.cs` | Role mutations must require `ROLE.CREATE`, `ROLE.EDIT`, `ROLE.DELETE`. | Controller only has `[Authorize]`. Methods lack `[RequirePermission]`. | Any user can create new roles or alter existing role metadata. | Decorate `CreateRole` with `[RequirePermission("ROLE.CREATE")]`, `UpdateRole` with `[RequirePermission("ROLE.EDIT")]`, `DeleteRole` with `[RequirePermission("ROLE.DELETE")]`. |
| **GAP-SEC-03** | **CRITICAL** | Security / Permission Assignment | `Backend/ERP/API/Features/Security/RolePermissionController.cs` | Assigning permissions to a role must strictly require `ROLE.EDIT` or `PERMISSION.MANAGE`. | Endpoint `POST api/RolePermission/batch` only checks `[Authorize]`. | Unprivileged users can grant arbitrary permissions to roles, enabling full privilege escalation. | Add `[RequirePermission("ROLE.EDIT")]` to `RolePermissionController.BatchAssign`. |
| **GAP-SEC-04** | **CRITICAL** | Security / User Role Assignment | `Backend/ERP/API/Features/Security/UserRoleController.cs` | Binding a user to an administrative role must require `USER.ASSIGN_ROLE`. | Endpoint `POST api/UserRole` only has `[Authorize]`. | Any user can assign themselves or others to the `Tenant Admin` role. | Add `[RequirePermission("USER.ASSIGN_ROLE")]` to `UserRoleController.AssignRole`. |
| **GAP-MD-01** | **HIGH** | Master Data / Branches | `Backend/ERP/API/Features/Domain/BranchController.cs` (lines 36-136) | Reading branch definitions must require `[Authorize]` and `BRANCH.VIEW`. | Class and methods lack `[Authorize]` and `[RequirePermission("BRANCH.VIEW")]`. | While company scope is checked manually in code, an anonymous caller with tenant context can invoke endpoint. | Add `[Authorize]` to `BranchController` and `[RequirePermission("BRANCH.VIEW")]` to `GetBranches` and `GetBranch`. |
| **GAP-MD-02** | **HIGH** | Master Data / Companies | `Backend/ERP/API/Features/Domain/CompanyController.cs` (lines 53-120) | Querying company entities must require `[Authorize]` and `COMPANY.VIEW`. | `GetCompanies` and `GetCompany` lack `[Authorize]` and `[RequirePermission("COMPANY.VIEW")]`. | Inconsistent with `CreateCompany` which has `[RequirePermission("COMPANY.CREATE")]`. | Add `[Authorize]` to `CompanyController` and `[RequirePermission("COMPANY.VIEW")]` to read actions. |
| **GAP-FE-01** | **HIGH** | Master Data / Company Setup | `Frontend/Web/src/app/core/services/company.service.ts` (lines 133-147) | Creating a branch must call a backend API endpoint (`POST api/companies/{id}/branches`) with transactional persistence. | `createBranch` generates a random string (`'br-' + Math.random()`) and writes only to browser `localStorage`! | Violates architectural rules; branches created in wizard are lost on logout/cache clear and are invisible to other users/backend. | Implement `POST api/companies/{id}/branches` in backend `BranchController` and update `CompanyService.createBranch` to call it. |
| **GAP-FE-02** | **MEDIUM** | Layout & Guards / Workspace | `Frontend/Web/src/app/core/auth/auth.service.ts` (lines 40-47) | `isTenantStaff()` should check the 19 standard roles seeded in Flow B. | Checks hardcoded legacy role names: `'Tenant User'`, `'Branch User'`, `'Viewer'`. | Legitimate operational users assigned standard roles (e.g., `Sales Officer`, `Inventory Officer`) could fail `isTenantStaff()` checks. | Update `isTenantStaff` to check for Flow B standard operational roles or verify membership in any non-customer tenant role. |
| **GAP-FE-03** | **LOW** | Layout / Navigation Menu | `Frontend/Web/src/app/layout/tenant-layout/tenant-layout.component.ts` (lines 203-208) | Sidebar links for Dispatch Notes and Sales Invoices should check their specific permissions. | Menu uses `canViewSales()` which checks only `SALES_ORDER.VIEW`. | Users who only have `SALES_SHIPMENT.VIEW` or `SALES_INVOICE.VIEW` (e.g. warehouse dispatchers or billing clerks) cannot see the menu. | Add `canViewShipments()` (`SALES_SHIPMENT.VIEW`) and `canViewInvoices()` (`SALES_INVOICE.VIEW`) to layout menu filtering. |
| **GAP-FE-04** | **MEDIUM** | Guards / Permission Bypass | `Frontend/Web/src/app/core/guards/auth.guard.ts` (lines 53-58) | `permissionGuard` should respect exclusions in role templates (e.g., `PRICE_CARD.OVERRIDE`). | Hardcoded `if (authService.isTenantAdmin() \|\| authService.isPlatformAdmin()) return true;` bypasses all permission checks in UI. | Frontend shows buttons/routes to Tenant Admin even when backend template strictly prohibits the operation. | Align `permissionGuard` to check user claims rather than blanket role bypasses for sensitive operations. |
| **GAP-FLA-01** | **LOW** | SaaS / Seeding | `Backend/ERP/Security/Services/SecurityBootstrapService.cs` (lines 172-193) | Standard roles should be strictly tenant-scoped (`TenantId = <tenantId>`). | A legacy global `Tenant Admin` (`TenantId = null`) is still seeded in `EnsureTenantAdminRoleAsync`. | Potential confusion between the legacy system-wide `Tenant Admin` role and the tenant-owned `TENANT_ADMIN` role instance. | Deprecate global `Tenant Admin` and rely entirely on `EnsureTenantStandardRolesAsync`. |
